### ⑧ 跨省同名地理实体（v0.2.22 · 先查后问，绝不静默猜哪一座）

有些名字不是一个地点，而是**一片区域**：用户说「幕阜山」，那是横跨湘鄂赣三省、绵延160 公里的山脉——平江天岳幕阜山（1596m，有索道）、九宫山（湖北通山，老鸦尖 1657m）、黄龙山（黄龙宗祖庭）、黄袍山、太阳山、大幕山（花海星轨），是完全不同的六趟旅行。

**给单一归属在这里不是"不够精确"，是结构性错误**——上层拿到单一归属会直接开始排程，用户到了现场才发现走错，那是**静默错误**：不报错，只是让人白跑一趟。

判定走 `references/geo_ambiguous.json` + `scripts/geo_disambiguate.py`：

```python
import geo_disambiguate as gd
r = gd.probe("幕布山", user_text="想找个山看日出", origin="岳阳")
# r["recommended"] → 锁定/推荐的候选 id
# r["card"]       → 已排好版的「先查后问」澄清卡，可直接呈现
```

**执行顺序（不可颠倒）**：

1. **先查**：一律先跑 `candidates()` 拿到全部候选，**不允许空手提问**。
   - ❌「请问你想去哪个幕阜山？」——用户不知道有几种选项，无法回答，只能猜。
   - ✅ 先把六个候选连同差异维度（位置/海拔/看什么/多远/有没有索道/有什么坑）摆出来，再问。
2. **锚点优先于意图**：用户已说「临湘那边」「通山那边」，直接锁定那一支，**不再问第二遍**。锚点是用户明确指定，不能被模型启发式覆盖。
3. **有诉求才排序**：用户说「看日出／避暑／拜佛／星轨」，按 `intent_fit` 加权并**说明理由**。用户没说诉求，**不推荐**，只列选项。
4. **意图拉不开时用距离决胜**：平江与九宫山都能看日出（2.85 vs 2.40），此时距离决定当天回不回得来——但**仅在双方都明确匹配该意图时**才允许距离翻盘。黄龙山看日出仅 0.5 分，它离得近是假优势（它以拜佛见长），不能靠「近 35km」挤上去。**把地理距离当产品匹配度是伪精确。**
5. **纠偏当场说**：口误必须当场告知，不得默默替换。「临湘那边的幕布山」——天岳幕阜山实际在**平江县南江镇**，临湘是隔壁县级市，走错要多花一小时山路。「幕布山／幕埠山」是错字（正确为「幕阜山」fù），按错字在票务平台搜不到主景区。

**必须写进交付物的**：
- 命中 `decision_hooks` 的坑必须体现（如「看日出须住山上——景区 08:00 才开，日出点位不在日间开放时段内」，这一条直接决定要不要订住宿，不是背景介绍）。
- 歧义未消解前**不锁行程天数、不排时刻、不报总价**——分母都不确定，算出来的数字是假的。
- 经纬度为示意坐标，只用于粗略距离与方向判断，**不得用于导航**；门票/开放时间属 volatile，标注需当日核验。

**覆盖范围**：`geo_ambiguous.json` 只收「高频会问、且各候选体验差异大」的条目（当前：幕阜山、五指山、天柱山/南岳）。冷门同名山查不到就走常规判定或标unknown 待查，**不臆造候选**。
