# 渲染规范 · 版式定稿 · 设计签名

> **按需加载**：①准备改版式/改 `render_compact.py` 时；②需要确认某章节渲染规则时。常规出册只要按下方「默认渲染命令」跑即可，**不需要读本文件**——版式已固化在渲染器里。

**默认渲染命令**：

```bash
python scripts/render_compact.py --plan plan.json --research research.json \
  --out 旅行小册子.html --title "标题"
```

### 第 6 步：渲染 A5 紧凑卡册小册子

```bash
python scripts/render_compact.py --plan plan.json --research research.json --out 旅行小册子.html --title "标题"
```

> `--research research.json` 可选：传入攻略研读沉淀的 ugc 数据，渲染进 §10「攻略核验 · 数据补充」条件子块（无数据不渲染，见「攻略检索模式 · 研读沉淀」）。

**视觉规范（A5 紧凑卡册 · v0.1.14 定稿 · 权威）**：米白底 `#F7F4EE` + 深墨绿主色 `#0F4C3A` + 14px 正文 + 行高 1.55 + 780px 版心居中；正文采用 bullet list + emoji 标签 + TIP/WARN/NOTE 三色边线小贴士 + 12.5px 时序网格（逐日时间锚点）+ 行前倒排 T-7d/T-3d/T-1d/D-day 时间线。**默认不配图、不渲染大块卡片、禁止大面积留白**。

**标准排版规范（v0.1.14 定稿 · 权威）**：本技能所有小册子的版式以根目录 [`排版规范.md`](排版规范.md) 为唯一标准，出册前须按其中的「验收清单」自检。要点：① 版心固定 `max-width:780px` 居中（紧凑卡册节奏，严禁擅自加宽到 860/1080）；② 固定 10 章节 § 01-§ 10（路线总览 / 怎么去 / 逐日动线 / 季节 / 拍摄 / 住宿 / 预算 / 清单 / 安全 / 冷知识），目录与板块一一对应；③ 板块自动编号 `§ 01` 起；④ `h2` 18px，`h3` 14.5px，`body` 14px，`line-height:1.55`；⑤ 章节块无卡片包裹、直接 `border-bottom:1px solid var(--line)` 收尾，section padding `14px 0 12px`（紧凑）；⑥ **每章节必填实质内容**——禁止空标题 / 占位框 / 留白大于 1 个空行；⑦ **零图纯文字**，任何配图均不接入；⑧ TIP/WARN/NOTE 三色边线小贴士取代大卡片（如 `TIP：xxx`、`WARN：xxx`、`NOTE：xxx`）。渲染器 `scripts/render_compact.py` 即该规范的代码实现；调整版式须同步改 `render_compact.py` 的 `HTML_TPL` 块并重建 `worldstip-travel-planner-v0.1.14.zip`。`scripts/render_booklet.py` 保留作为 Apple 风备选（旧版），不再作默认。

**§ 02 怎么去 · 明确通行方式规则（v0.1.14 新增，硬性）**：

- **用户已明确通行方式**（如「骑摩托去」「坐飞机去」「自驾」）→ **只渲染该方式的通行卡**，严禁再出 6 方式比选表（高铁/普铁/飞机/客车/轮船/自驾全列）。已明确的 style（`moto`/`roadtrip`/`cycling`）由渲染器自动识别；其他明确方式（飞机/高铁）由编排层在 transit.json 里显式标注 `"explicit": "飞机"`（或 plan 的 `transport_explicit` 字段）。
  - `moto` → 摩托通行卡：路线 + 逐日骑行量 + **五项门禁灯位**（准驾证件/头盔/高速准入/禁摩城区/续航加油）+ 禁摩限行提示（`plan["special"]` 结构化渲染，**严禁直接 dump dict**）+ 一行「应急备选」（摩托受阻时的高铁/普铁，仅一行，不成表）。
  - `flight` / `hsr` → 单方式卡：时长 + 票价 + 一行备选 + 估算免责。
- **未明确通行方式** → 才出公共交通比选表（含推荐度标注 + 推荐理由）。
- **`plan["special"]` 渲染纪律**：`special` 是 `{kind, title, items:[{主题, 内容}]}` 结构化 dict，必须逐条取 `items[].内容` 渲染为 callout；**任何情况下不得把 dict 直接 `esc()` 进 HTML**（会产生 `{'kind': 'moto'...}` 乱码——v0.1.14 已修复此缺陷）。

**§ 08 行前清单 · 卡片化纪律（v0.1.14 新增）**：装备清单按类别渲染为 `.pack-grid` 2 列网格卡片（每类一张卡：图标 + 类名 + `·` 分隔的内联条目），`画像重点`/`季节性` 两张通栏卡（`.pack-card.full`）；严禁再用 `<h4>类别</h4><ul><li>...` 长列表（拖长页面、阅读断裂）。

- **统一深墨绿主色（不做每板块变色）**：v0.1.14 定稿以用户确认的「赤峰速查卡册 / Disney 页 / 第比利斯到达 A5 PDF」三参考母版为准——全册统一使用 `--accent`（#0F4C3A 深墨绿）主色，板块靠「§ 序号 + 标题」区分，不再给每个板块分配单独强调色、不再用左侧色条、不再用毛玻璃导航条。这样阅读节奏紧凑、内容填满、绝不显空。
- **配图（永久关闭 · 不再开启）**：**默认绝不接图源、不配图**——不检索 Wikimedia/网络图源、不写 `plan["cover_url"]` 与 `plan["images"]`，直接产出纯文字小册子。**这是 v0.1.14 起的新默认纪律，不可由用户开关覆盖**——因为 A5 紧凑卡册版式的核心价值就是「字段密集、零图、零留白」，任何配图都会破坏节奏。强制纯文字可省掉整段检索开销、加快出册。渲染器不再提供 `--no-images` 开关（已删）；原 `render_booklet.py` 的 Wikimedia Commons 热链、`cover_url`、`images`、授权署名等代码保留但不再由 `render_compact.py` 调用。
- 右下角悬浮按钮组（FAB，纯前端零依赖）：**📄 保存为 PDF / 📅 导出 .ics 日历 / 📋 复制行程 / ⬆️ 回到顶部**。借鉴同类路书方案的交互思路但**不引入第三方开源地图组件联动**；行前清单加 `localStorage` 勾选记忆（按行程哈希隔离，刷新不丢勾选）。渲染产物内嵌 `<script id="trip-data">` 完整行程 JSON（数据-呈现分离，便于二次处理）。

**板块自动编排**：行程概览 → 季节与气候方案 → 逐日动线（**点到点衔接卡** + 可选离线示意图） → **可执行性体检** → 交通比选 → **绿色出行 · 碳足迹与成本对比（有跨城里程才渲染）** → 实地调研 → **真实反馈（UGC，有数据才渲染）** → **避雷 · 别踩这些坑（有踩坑类 UGC 才渲染）** → 天气预检 → **天气突变预案 · Plan B（命中恶劣天气阈值才渲染）** → 景点门票 → 出行须知 → 住宿 → 预算 → **行前准备清单** → **安全提醒** → **高反应急与就近就医（命中高原目的地才渲染）** → **证件与财物遗失应急（离家常带证件的行程才渲染）** → 出行偏好/冷知识/受众专属（有数据才渲染）。

### 设计签名与体验增强（v0.0.7）

v0.0.7 在保持「零依赖 / 多语言 / 本地库优先 / 内容克制」底牌的同时，针对同类技能对比中暴露的视觉与体验短板做了一轮补强：

**① 内联 SVG 图标系统（去 emoji，premium 质感）**
全册 40+ 处图标从 emoji 改为统一描边内联 SVG（`icon()` 自动映射，向后兼容），视觉一致、可随板块强调色变色，告别"系统 emoji 在不同平台长不一样"的廉价感。

**② 三大数据可视化签名组件（纯 SVG·零依赖）**
- **预算环形图**（`donut_svg`）：各分项占比环形图 + 图例，一眼看钱花在哪。
- **体力曲线**（`stamina_svg`）：逐日强度折线，配合每日**弹性评分★**（固定时间锚点越少越灵活），让"哪天累、哪天好调"可视化。
- **行程动线示意图**（`route_map_svg`）：天数节点沿波浪路径排布（示意，非地理精确），跨城/自驾一眼看懂走向。

**③ 可执行性体检关卡**（`_sec_feasibility` + `references/feasibility_check.json`）
规则型自检：单日点位上限、在外最晚时段、高海拔适应日、长线疲劳、跨城转场缓冲。**诚实标注非实时**——只基于经验阈值，出行前以官方实时信息复核。这是参考行业通行做法补充的「可执行性体检」能力。

**④ 跨会话偏好档案（`scripts/profile.py`）**
六维度（节奏/作息/饮食/体力/住宿/雷区）落 `~/.aitrip/profile.json`，编排前 `recall`、结束后 `remember`，下一次自动沿用，解决"每次都要重新交代偏好"的断点。

**⑤ 复盘回写（`scripts/reflect.py`）**
行程后把真实反馈（准确度/安全/预算/舒适度/内容，1-5★）沉淀进 `~/.aitrip/feedback.json`，形成可复用的经验飞轮。

**⑥ 多形态交付 + 双版式**
- **Markdown 导出**：`--format md` 输出纯文本小册子，便于贴入便签、即时通讯软件与文档。
- **紧凑版**：`--variant light` 精简逐日描述与可选可视化，给"只看结论"的用户。

**⑦ 预算 AA 人均分摊**
人数 > 1 时显式展示"AA 分摊：每人约 ¥X（全团合计 ¥Y）"，住宿/租车等大项已区分全团与人均两档。

**⑧ 数据可信度透明徽章（v0.0.8，直面"数字真实性弱"）**
预算与交通板块标题统一挂「估算 ⓘ」角标，hover 提示"里程/票价/开放时间为经验估算，以官方实时为准"。这是针对复对比中暴露的"数字真实性弱"劣势做的**诚实化补强**——不假装精确，而是把"可信度边界"明示给用户。

**⑨ 动线示意图带段里程/方式标注（v0.0.8，缓解"无真实地图"）**
`route_map_svg` 升级：跨城/自驾时，节点间标注"飞机 3300km""自驾 1312km"等段里程与交通方式（数据由编排注入，缺失则不出）。虽非地理精确地图，但让自驾/跨城用户一眼看懂"怎么连、每段多远、用什么方式"，是对"无真实地图"劣势的**轻量替代**。

**⑩ 地图渲染策略：真地图优先，失败即降级、绝不用 SVG（v0.1.17）**
生成出行报告的地图层按以下优先级，**任一环节失败立即跳到下一档，绝不卡住或反复重试**：
1. **地图服务 API（首选）**：能拿到驾车折线/坐标就渲染真实路线地图（`live_api` 驾车路径接口，需配置地图服务 key）。
2. **备用地图服务 API（备用）**：地图服务无 key / 调用失败 / 返回空折线时，改用备用地图服务（`GEO_PROVIDER=backup`）出图。
3. **文字描述（兜底）**：地图服务、备用地图服务都拿不到真实地图数据时，**不画任何图**——退回 §02「怎么去」的点到点衔接卡 + 逐日动线文字（出发→到达 + 方式 + 里程 + 时长 + 费用），坐标序列以文字路书形式呈现。

**硬性纪律**：
- **禁用 SVG 示意图作为降级**：过去的 `--map offline`（SVG 等距投影手绘折线）和 `route_map_svg` 示意折线**不再用于报告地图层**——用户明确反馈"不用真地图太难看"。要么真地图，要么纯文字，**中间态的 SVG 假地图一律不出**。
- **失败即切、不纠缠**：地图 API 调用一旦失败（超时/无 key/空结果），**立即**改走下一档策略，不做多次重试、不阻塞出册。保证报告"一定出得来"。
- **准确性 + 美观双保**：降级到文字时，靠紧凑卡册版式、三色边线 TIP/WARN/NOTE、字段密度保证美观；里程/时长用 `distance_source` 诚实标注（实算✓/估算ⓘ），保证不误导。

**行前准备清单**（`references/packing_checklist.json`）：通用必备 + 按本次交通方式专项（公共交通/自驾/摩旅/房车/骑行/徒步）+ 按季节加项 + **T-7/T-3/T-1/当天 倒排时间线**。

**安全提醒**（`references/safety_playbook.json`）：通用安全 + 按本次交通方式（飞机/火车/客车/轮船/自驾/摩旅/房车/骑行/徒步）+ 按场景（城市/山区/水域/古镇民俗）+ 应急预案模板。条件化表述，不做绝对化承诺。

### 第 7 步：交付说明

1. 小册子可直接打开，保存 PDF 点右下角按钮或 Ctrl/Cmd+P。
2. 票价需自行核实（12306/客运站/港口官方）。
3. 天气、开放时间为生成时状态。
4. 可具体说明调整（增减天数/改节奏/换住宿区域）后重新生成。
