## 第 1 步：需求收集细则（弹窗式 · 2 轮收齐）

### 第 1 轮（4 题，一次抛出）

| 题 | 预填选项（覆盖高频 80%） | 长尾 |
|---|---|---|
| Q1 出发地 | 4 个常见城市（按上下文推断） | Other 填空 |
| Q2 目的地 | 已知→直接确认；未知→给 2–3 个候选，**不擅自定死** | Other 填空 |
| Q3 天数 | 1天(当天来回) / 2天 / 3天 / 4天+ | Other 填空 |
| Q4 出行方式 | 公共交通 / 自驾(汽车·房车) / 摩托 / 骑行 / 徒步 | Other 填空 |

### 第 2 轮（4 题）

| 题 | 预填选项 |
|---|---|
| Q1 出行月份/日期 | 本月 / 次月 / 3 月内 / 具体日期（决定季节气候结论） |
| Q2 人员构成 | 情侣·夫妻 / 家庭带娃 / 带长辈 / 朋友同行 / 独自（决定分房） |
| Q3 预算区间(人/天) | ¥300-500 / ¥500-800 / ¥800-1500 / ¥1500+ |
| Q4 体力与节奏 | 紧凑刷景 / 适中留白 / 慢游发呆 |

### 第 3 轮（条件触发）

仅当以下任一成立才追加：① 自驾 → 车辆类型(ev/pveh/fuel/hybrid)；② 摩托 → 排量(150/250/400/500cc+) 与是否跨市区（跨市区判定长途/短途，影响续航与加油策略，查 `vehicle_range.json`）；③ 用户已提必去/必避/饮食禁忌/住宿偏好需确认。**未触发则跳过，不得为凑字段强行加轮。**

### research.json 的 ugc 键字段契约

每条一个对象：

- `kind`：`踩坑` / `价格` / `体验` / `贴士`（卡片按类型配色）
- `where`：具体地点（如"岳阳楼"）
- `text`：一句话结论（口碑 / 真实价 / 踩坑点）
- `src`：`实测`（亲历 / 带图实证）/ `官方`（官方·公示）/ `检索`（公开搜索结论）
- `source`：来源名称（如"岳阳楼景区官号"），便于溯源与复核
- `recency`：`近6月` / `近1年` / `更早`（相对档，保留以兼容旧渲染器）
- `verified_on`：**绝对核验日期**（YYYY-MM-DD，必填）；超期自动标「需出行前复核」
- `confidence`：`实测` / `官方` / `检索`（与 `src` 对齐的证据等级，渲染器打来源徽章）
- `category`：`ticket` 票务预约 / `transit` 交通衔接 / `queue` 排队时段 / `food` 餐饮 / `pitfall` 避雷踩坑 / `photo` 机位拍摄 / `tip` 贴士
- `sources` / `multi`：多来源合并时登记全部来源名与 `multi:true`，渲染徽章「多源印证」

### 攻略研读沉淀通道

从公开攻略研读提取的结构化事实经 `scripts/guide_digest.py` 校验合并（三元组缺一即拒、同事实多源升级、`--merge research.json` 合并写回）后落入 `ugc` 键，由 `render_compact.py --research research.json` 渲染进 §10 条件子块「攻略核验 · 数据补充」（无数据整块不渲染、不外露链接）。

## 交通圈层判据速查

| 圈层 | 判据 | 交通推荐 | 纪律 |
|---|---|---|---|
| **市内/同城** | ≤30km 或坐标缺失（景点/街区/门店不在城际库） | 公交 / 地铁 / 出租车 / 网约车（短驳骑行、超短步行） | **不推高铁/飞机/普铁**；坐标缺失时先问用户「市内还是跨城」再定 |
| **近郊/周边** | 30-150km | 自驾优先 / 客运班车；高铁仅当「确已通高铁且单程≥50km」才列入并标前提 | 不默认推高铁飞机；当天来回必须留返程余量 |
| **跨城/跨省** | >150km | 高铁 / 普铁 / 飞机 / 客车 / 轮船 / 自驾 六方式比选 | 跨省必须比「直飞/中转/铁路」并给到达站落地建议 |

> 实现：`scripts/plan_transit.py`。注意同，距离为 0 判同城而非「坐标缺失」——
> `dist is None` 才是坐标缺失，`dist == 0` 是同城。
