### 1.9）远程 4 维约束（国界改变的是约束，不是求解器）

排程 / 交通比选 / 预算 / 可行性体检 / 渲染与国界无关，**0 改动复用**。远程真正新增的是 4 个国内不存在或权重极低的约束维度（`scripts/outbound_constraints.py`）：

| 维度 | 内容 | 为什么国内没有 |
|---|---|---|
| ① 准入可行性 | 证件/准入许可/疫苗/保险 | **硬门槛，不过则行程为 0**（国内身份证走天下） |
| ② 货币与购买力 | 汇率量级、时差、刷卡/支付、小费 | 国内无 |
| ③ 标准与文化 | 行驶方向、插头电压、禁忌、药品管制 | 国内无 |
| ④ 领事与制度安全 | 治安、陷阱、季节风险、12308 | 国内有 110/120 统一兜底，远程需逐国映射 |

**板块只是这 4 维的渲染出口，不是功能本体。** 每条远程内容都必须能回答「它如何改变我的行程安排」，否则不进册。


### 1.10）远程「答不出错」核查（v0.3.1 新增）

国外的可以做，但**问到就必须答对**。`scripts/outbound_safety.py` 把这句话变成
5 条可验证防线，任一失败即不许对外承诺远程能力：

| 防线 | 检查内容 |
|---|---|
| 1 查不到 → unknown | 瓦坎达/苏联/锡兰/北塞浦路斯等必须走灰灯，**绝不能给绿灯**（绿灯=回答「没问题」=编造） |
| 1b 误映射探针 | 迪拜→阿联酋（非申根）、罗马→unknown、曼谷→泰国、第比利斯→格鲁吉亚；申根城市未列映射一律不猜 |
| 2 稳定性证据 | 四张基线表都必须有 volatility 等级或 `_updated` 日期戳 |
| 3 结论可溯源 | 表级 `_sources`（官方来源）+ `_updated`，缺一半即失败 |
| 4/5 门禁四灯 | 四灯必须齐备；准入许可 15 天办、3 天后出发必须判红灯并出拦停页（含行动项，不是只拦不教） |

```bash
python scripts/outbound_safety.py          # 30 项断言
python scripts/outbound_safety.py --strict # 任一失败退出码 1
```

**v0.3.1 修掉的远程漏答**：互免准入许可名单里有 29 国（含格鲁吉亚），但 `countries`
主键只有 10 个 → `_pick_country` 遍历不到名单 → 问「格鲁吉亚要不要准入许可」只能答
unknown（灰灯）。数据在表里、代码没接上。现已把名单国名 + 括号别名（「波黑」→
全名，归一化后才能命中 `in_mutual` 判定）接入可解析集合，并补全三张表缺失的
`_sources`。同步修复 `render_booklet.py` 的 try 耦合缺陷（`gate_card` 缺失会连带
关闭可信度内核）。
