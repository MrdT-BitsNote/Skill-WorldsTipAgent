## 攻略检索模式（按需 · v0.1.28：对话清单 + 研读沉淀进册）

**定位**：小册子回答「这趟怎么走」；本模式回答「别人是怎么玩的 / 有没有现成攻略可以参考」。用户**明确要攻略时才启动**，默认不触发、不打扰小册子流程。

**触发词（口语/句式都要命中）**：找攻略、查攻略、搜攻略、有没有攻略、看看别人怎么玩、找点游记、游记参考、攻略参考、有什么攻略、帮我找找 X 的攻略、把攻略整理进小册子、X 怎么玩（用户要「参考别人」而非要成品行程时）。

**意图判定（两条输出路径，按用户要什么分流）**：
- **只要参考**（「找攻略看看」）→ 只出**对话清单**（带可点击原文链接，见下方纪律），不出小册子。
- **要行程 / 小册子**（「帮我规划 X」「把攻略整理进小册子」）→ 走小册子流程，检索到的攻略**研读后沉淀进小册子**（见「研读沉淀」小节）；同时可在对话里附清单。
- 命中触发词但两者都要 → 先列清单，再问是否沉淀进册。

**执行流程**：
1. **轻量确认（1 轮，最多 2-3 项）**：目的地（必填）/ 主题或玩法侧重（可选：美食/徒步/摄影/亲子/省钱…）/ 出行方式（可选）。用户已说清则跳过不追问。
2. **定向检索（宿主 WebSearch / WebFetch，技能自身不抓取）**：按「目的地 × 主题 × 方式」组 2-4 条查询词并行搜；宿主已接入问答社区/社交平台/点评平台/短视频平台类外接 MCP 时优先调用做交叉核验（多源印证真实口碑），无 MCP 则纯 WebSearch，并**如实标注核验深度**。只取「标题 + 来源 + 链接 + 核验日期 + 一句话要点」五要素，不保存原文、不接 Cookie。
3. **交叉核验**：攻略里涉及的价格/开放时间/预约规则等 volatile 事实至少 2 个单独来源，偏差 >30% 标区间并写「以官方当日为准」；孤例体验标「个别反馈」。
4. **校验落地（`scripts/guide_list.py`）**：把整理好的 JSON 喂给脚本——URL 合法性校验（**禁手拼/禁票务域名/禁交易路径**）、按 URL 归一化去重、按匹配度/可信度/日期排序、时效告警、渲染 Markdown 清单。`--strict` 有拒绝即退出码 1（可入回归）。

**条目五要素**：标题/主题 · 来源（名称 + 类型：官方/问答社区/点评平台/社交平台/短视频平台）· 可点击原文链接 · 核验日期（YYYY-MM-DD）· 一句话要点 + 可信度档位（官方 > 多源印证 UGC > 孤例标「个别反馈」；未核验挂灰灯「待查」）。

**输出纪律（对话清单）**：
- **限量精选**：3-8 条，按与用户目的地/主题/方式的匹配度排序；先砍后排，不堆量。
- **时效标注**：>30 天的价格/开放/排队/限流信息挂「临近过期」；>90 天的体验类标「参考价值待定」。
- **查不到就说查不到**：没有合适攻略时如实告知 + 给检索词建议，**绝不编造标题或链接**。
- **多语言**：用户用什么语言问，标题/要点用什么语言（链接本身保持原样）。

### 攻略研读 → 数据沉淀（进小册子 · 让行程数据更完整可信）

**要解决的问题**：本地 `references/` 是稳定基线，票价/开放/预约/排队/机位/餐饮口碑这些 volatile 与体验类信息，公开攻略里最全——把**研读后的结论**沉淀进小册子，行程数据更完整、更可信。

**沉淀流程（研读 → 校验 → 进册）**：
1. **研读提取**：从检索到的攻略原文提取**可核验的结构化事实**，每条五字段——`fact`（一句话结论）/ `category`（ticket 票务预约 · transit 交通衔接 · queue 排队时段 · food 餐饮 · pitfall 避雷踩坑 · photo 机位拍摄 · tip 贴士）/ `source`（来源名称）/ `source_type` / `verified_on`（YYYY-MM-DD）。**必须转写为可执行项**（具体名字 + 数字 + 时间窗，如「金鞭溪排队高峰 10-11 点，建议 8 点前入园」），**严禁照搬原文段落**（>160 字即拒）。
2. **校验合并（`scripts/guide_digest.py`）**：三元组缺一即拒（灰灯不进册）；同一事实 ≥2 个单独来源自动合并升级为「多源印证」；日期拒未来；输出**兼容既有 ugc 结构**（kind/where/text/src/source/recency/verified_on/confidence + 新增 category 分组字段），`--merge research.json` 直接合并写回、同事实不重复追加；`--strict` 有拒绝退出码 1。
3. **渲染进册（`render_compact.py --research research.json`）**：渲染进 **§10「出发前多知道一点」内的条件子块「攻略核验 · 数据补充」**——按 category 分组、每条带来源徽章（官方/多源印证/检索）+ 来源名称 + 核验日期；volatile 类 >30 天、体验类 >90 天自动挂「需出行前复核」。**无有效条目整块不渲染**（沿用「无数据则整段不渲染」纪律）；子块**只呈现来源名称与日期，不外露任何链接**。
4. **诚实兜底**：宿主无联网能力时跳过沉淀，仅用内置 references，并在小册子如实标注"未做实时公开核验"。

**沉淀纪律（与既有可信度内核一致）**：只取「结论 + 来源 + 日期」三元组、不保存原文；票价/限流/开放时间以官方实时为准，口碑仅供参考并提示甄别广告软文；查不到即灰灯，绝不编造。

**⚠️ 链接标准边界（对既有「禁可点击外链」纪律的窄口例外，焊死不得越界）**：
- 本模式是**唯一允许可点击外链**的场景，且**仅限信息类攻略/游记/官方信息原文**、**仅限对话清单**。
- **禁止**：票务/预订/交易/代下单深链（含任何售票站点与下单路径）；需要登录/Cookie 才能看的内容；站外引导话术（「点击购买」「立即预订」）。脚本层已机械拦截。
- **沉淀进册的内容绝不带链接**：小册子/HTML/PDF 保持零外链（交通查询层纪律不变）——进册的只有「结论 + 来源名称 + 核验日期」。
- 规范若收紧，随时可收回本例外（退回「只列来源+日期+要点、无链接」）。
